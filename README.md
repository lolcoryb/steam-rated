# Rated

New on Steam, sorted by review score.

Steam's store can sort new releases by date or by "relevance," but not by review
tier — so there's no way to ask it the obvious question: *what came out recently
that people actually like?* This does that. A scheduled job crawls Steam's own
search endpoint every morning, keeps the review summary Steam already computes
for every game, and a static page lets you filter and sort it.

**[Setup instructions →](SETUP.md)** — about ten minutes to a public URL.

## What's here

```
docs/index.html        the app; reads docs/data.json, no build step, no dependencies
docs/data.json         generated by the crawler and committed by CI
scripts/fetch_steam.py the crawler
scripts/test_parser.py parser tests, run in CI before every crawl
.github/workflows/     the daily refresh
```

The page is plain HTML with no framework and no external requests except Steam's
image CDN. GitHub Pages serves it; the data sits next to it as a JSON file.

## Using it

**Presets** across the top are the usual questions:

- **Best new releases** — Very Positive or better, last 30 days
- **Hidden gems** — 90%+ positive but under 500 reviews
- **Good and under $15**
- **Free**
- **Proven hits** — 1000+ reviews, the releases that broke through
- **Avoid these** — Mixed or worse, worst first

**Filters** compose: click a rating chip to isolate that tier, click others to
add them back. Time window, tag, minimum reviews, maximum price and search all
narrow further. Sort by any column in table view.

**Sharing a view:** the filter state lives in the URL. Set up a view you like and
hit *copy link* — whoever opens it lands on the same filters.

## The part that trips people up

Steam's tiers depend on review **count**, not just percentage:

| Tier | Positive % | Reviews needed |
|---|---|---|
| Overwhelmingly Positive | 95–100% | 500+ |
| Very Positive | 80–100% | 50+ |
| Positive | 80–100% | 10–49 |
| Mostly Positive | 70–79% | 10+ |
| Mixed | 40–69% | 10+ |
| Mostly Negative | 20–39% | 10+ |
| Negative | 0–19% | 10–49 |
| Very Negative | 0–19% | 50–499 |
| Overwhelmingly Negative | 0–19% | 500+ |

So a game released last week essentially cannot be Overwhelmingly Positive — it
needs 500 reviews first. Set the window to 7 days and the top tier will look
empty; that's the threshold, not a bug.

This is exactly what **Hidden gems** is for: it sorts by raw percentage instead
of by tier, which surfaces the 96%-with-80-reviews releases that haven't been
promoted yet.

## Crawler options

```
python scripts/fetch_steam.py --days 180
```

| Flag | Default | |
|---|---|---|
| `--days N` | 180 | How far back to crawl. The page slices shorter windows out of this client-side, so crawl wide and filter in the browser. |
| `--min-reviews N` | 10 | Below 10 reviews Steam doesn't assign a tier at all. |
| `--verify-budget N` | 400 | Max developer/genre lookups per run. Cached and committed; a daily run only handles new games. `0` skips it. |
| `--cc de` | us | Store region for prices. |
| `--keep-junk` | off | Stop filtering demos, soundtracks and DLC out by name. |

It refuses to overwrite `data.json` if the crawl returns nothing, so a failed run
leaves the last good data in place.

## If it breaks

It reads Steam's public search HTML, so a store redesign can break parsing. The
regexes are at the top of `scripts/fetch_steam.py` — `ROW_RE`, `TOOLTIP_RE`,
`SUMMARY_RE`. CI runs `scripts/test_parser.py` against a saved sample of real
Steam markup before every crawl, so a red build usually points straight at the
line that changed.
